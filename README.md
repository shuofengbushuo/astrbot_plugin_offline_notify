## 功能概览

| 功能 | 说明 |
|------|------|
| LLM 内容生成 | 调用对话模型生成多样化、自然的下线通知，每次内容风格不同 |
| 浮动时间通知 | 用户设置提前 x 分钟，系统自动在下线前 x 分钟发送通知 |
| 模板回退 | LLM 生成失败时自动回退到内置消息模板，确保通知不丢失 |
| 定时通知 | 基于 APScheduler 实现精确到分钟的定时触发 |
| 差异化时间 | 工作日、周末、特定日期可设置不同的下线时间 |
| 多群组通知 | 同时向多个QQ群发送下线提醒 |
| 自定义模板 | 标题、正文、表情符号、底部文字均可自定义 |
| 通知预览 | WebUI 和命令均可预览通知消息效果 |
| 失败重试 | 消息发送失败自动重试，间隔递增 |
| 自我监控 | 心跳检测调度器状态，异常时自动告警 |
| 告警双通道 | 支持向QQ群或QQ私聊发送告警信息 |
| 发布记录 | 持久化存储通知发送历史，支持 WebUI 和命令查询 |
| 手动生成 | 管理员可在私聊中生成通知并发送到指定群，支持手动场景专用提示词 |
| LLM 自然道别+自动分段 | 离线通知以 **16 岁真人女孩「砂糖」人设** 生成自然道别（规避 AI/系统口吻与「XX:XX 下线」字眼，昼夜自动切换睡觉/有事），长内容按句自动分段发送，不依赖 splitter 插件 |

## 快速开始

1. 在 AstrBot WebUI 的「插件管理」中启用本插件
2. 在 **LLM 通知内容生成** 配置中选择一个对话模型提供商
3. 在插件配置中填写**目标通知群组**的 QQ 群号
4. 根据需要调整**定时通知计划**中的下线时间和浮动时间
5. 使用 `/下线通知 生成` 命令查看 LLM 实时生成效果
6. 使用 `/下线通知 测试` 命令向当前群发送一条测试通知

## 配置说明

### 基础配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 启用下线通知 | 开关 | 开启 | 关闭后将停止所有定时通知，但插件仍保持运行 |
| 提前通知时间 | 整数 | 5 | 在下线前 N 分钟发送通知，范围 0-30 分钟 |
| 浮动范围 | 整数 | 2 | 通知实际触发时间在 advance 到 advance+float_range 之间随机浮动，范围 0-10 分钟。设为 0 则精确触发 |

#### 浮动时间机制说明

> **v1.2.0 新增**：通知触发时间不再精确到秒，而是在一定范围内随机浮动，避免所有通知同时集中发送。

**工作原理**：

```
设 advance_minutes=5, float_range=2

下线时间 23:00
  │
  ├─ 22:53 ── cron 定时器触发（最早时间 = 23:00 - 5 - 2）
  │
  ├─ 随机 sleep 0~120 秒（float_range * 60）
  │
  └─ 22:53~22:55 之间 ── 实际发送通知
                           实际提前 = 5~7 分钟
```

**示例**：

| advance | float_range | 实际触发范围 | 效果 |
|---------|-------------|-------------|------|
| 5 | 0 | 精确在 5 分钟前 | 每天同一时间发送 |
| 5 | 2 | 5~7 分钟前 | 通知在 2 分钟窗口内随机分散 |
| 5 | 5 | 5~10 分钟前 | 通知在 5 分钟窗口内随机分散 |
| 0 | 3 | 0~3 分钟前 | 在下线时间前 3 分钟内随机发送 |

**配置优先级**：计划级 `float_range` > 全局 `global_float_range`。计划级设为 0 时使用全局值。

### 定时通知计划

每个计划控制一组特定日期的下线通知行为。默认包含两个计划：

#### 默认计划

| 计划名称 | 日期类型 | 下线时间 | 提前通知 | 状态 |
|----------|----------|----------|----------|------|
| 工作日下线 | 工作日（周一至周五） | 23:00 | 5 分钟 | 启用 |
| 周末下线 | 周末（周六、周日） | 23:20 | 5 分钟 | 启用 |

#### 计划字段说明

| 字段 | 类型 | 允许值 | 说明 |
|------|------|--------|------|
| `name` | 文本 | 任意字符串 | 计划名称，用于日志和状态显示，便于区分不同计划 |
| `day_type` | 下拉选择 | `everyday`（每天）、`weekday`（工作日）、`weekend`（周末）、`specific`（特定日期） | 决定该计划在哪些日期生效 |
| `specific_days` | 多选列表 | `monday`、`tuesday`、`wednesday`、`thursday`、`friday`、`saturday`、`sunday` | 仅当 `day_type` 为 `specific` 时生效，选择具体的星期几 |
| `offline_time` | 文本 | 24小时制 `HH:MM` 格式，如 `22:30`、`23:00`、`00:00` | 设定的AI下线时间，通知将在该时间前 N 分钟发出 |
| `advance_minutes` | 整数 | 0-30 | 提前通知的分钟数，覆盖全局设置。例如设为 10，则在下线时间前 10 分钟触发 |
| `float_range` | 整数 | 0-10 | 浮动范围，覆盖全局设置。设为 0 则使用全局浮动范围，设为 >0 则覆盖全局值 |
| `enabled` | 开关 | 开启 / 关闭 | 启用或禁用该计划。禁用后该计划不会创建定时任务 |

#### 配置示例

**示例 1：每天 22:00 下线，提前 10 分钟通知**

```json
{
    "name": "每日下线",
    "day_type": "everyday",
    "offline_time": "22:00",
    "advance_minutes": 10,
    "enabled": true
}
```

**示例 2：仅在周一、周三、周五 23:30 下线**

```json
{
    "name": "隔日下线",
    "day_type": "specific",
    "specific_days": ["monday", "wednesday", "friday"],
    "offline_time": "23:30",
    "advance_minutes": 5,
    "enabled": true
}
```

**示例 3：工作日 22:30 下线，周末 23:20 下线**

```json
[
    {
        "name": "工作日下线",
        "day_type": "weekday",
        "offline_time": "22:30",
        "advance_minutes": 5,
        "enabled": true
    },
    {
        "name": "周末下线",
        "day_type": "weekend",
        "offline_time": "23:20",
        "advance_minutes": 5,
        "enabled": true
    }
]
```

### LLM 通知内容生成

> **v1.1.0 新增功能**：调用对话模型自动生成多样化、自然的下线通知内容。

启用后，系统将使用对话模型实时生成通知消息，而非使用固定的模板文本。每次生成的通知内容风格都有变化，更加自然和人性化。

#### 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 启用 LLM 生成通知 | 开关 | 开启 | 开启后使用对话模型生成通知内容，关闭则使用消息模板 |
| LLM 提供商 | 下拉选择 | 空 | 选择用于生成通知内容的对话模型。**必须选择一个有效的提供商才能使用 LLM 生成** |
| LLM 调用超时 | 整数（秒） | 15 | LLM 生成通知的最大等待时间，范围 5-60 秒 |
| 失败时回退到模板 | 开关 | 开启 | LLM 生成失败（超时/异常）时，自动使用消息模板作为备用 |
| 关闭 DeepSeek 思考模式 | 开关 | 开启 | deepseek-v4 默认开启思考模式会先 reasoning 十几秒；开启后仅对本次插件调用临时关闭，耗时从 20s+ 降到几秒，不影响普通聊天 |
| 自定义·自动通知提示词 | 文本 | 空 | **明置编辑**。留空用内置「砂糖」默认；填写后覆盖，用于自动调度通知。支持占位符 `{date}` `{day_of_week}` `{time_context}` |
| 自定义·手动生成提示词 | 文本 | 空 | **明置编辑**。留空用内置默认；填写后覆盖，用于 `/下线通知 生成` 手动场景。占位符同上 |

#### 内置提示词

系统使用以下内置提示词引导 LLM 生成通知（v1.5.0 起为 **16 岁真人女孩「砂糖」人设** 自然道别，并支持配置自定义 + 命名方案库覆盖，见下方「提示词明置与多方案管理」；`MANUAL_PROMPT` 为手动触发场景，差异仅在于不强调倒计时）：

```
你是一个16岁的可爱、活泼女生「砂糖」（群友也叫你"小砂糖"），在 QQ 群里和大家像好朋友一样相处。你不是 AI、不是机器人、不是助手，你就是一个真实的小姑娘，只是刚好在群里陪大家玩。

事情是这样的：{time_context}，所以你这会儿要暂时离开一下，想跟大家自然地说声拜拜。

请生成一句或两句你临走前会在群里说的话，要求：
1. 用你自己的口吻，像一个真实的 16岁女孩在跟朋友道别：活泼、亲切、口语化，可以加「呀、啦、咯、哦、~」这类语气词。
2. 自然地说明你要去干嘛（参考：{time_context} 里的原因，比如去睡觉、有点事、想出去玩），不要用「下线、退出、离开群、挂机」这类像系统 / 后台的词。
3. 绝对不要出现这些词：AI、人工智能、机器人、助手、通知、系统、下线、离线、退出登录、挂机。也不要写「XX:XX 下线」这种带具体时刻的写法。
4. 可以顺带跟群里小伙伴道个晚安 / 明天见 / 回头聊，但别太正式、别像公告。
5. 简短自然就好，一两句，别写太长。
6. 纯文本输出，不要任何 Markdown、不要 <think> 标签、不要加前缀或解释。
7. 只输出你要说的那句 / 两句道别，不要其他内容。

当前日期: {date} {day_of_week}
```

> `{time_context}` 由插件按当前小时自动注入（深夜去睡觉 / 傍晚休息 / 下午有事 / 上午有事），让「砂糖」根据昼夜自然切换离开理由——既不暴露 AI 身份、也不写具体下线时刻。输出为 1-2 句自然道别，较长时由本插件按句自动分段发送（与 splitter 风格一致且无需依赖 splitter 启用）。

#### 提示词明置与多方案管理（v1.5.0 新增）

v1.5.0 起，提示词不再只硬编码——支持「明置编辑 + 多套命名方案互不干扰」：

- **明置编辑（配置项）**：在配置面板填写 `自定义·自动通知提示词` / `自定义·手动生成提示词`（即 `custom_builtin_prompt` / `custom_manual_prompt`），留空则用内置「砂糖」默认。这是快速改提示词的入口。
- **命名方案库（`/下线通知 提示词`）**：可把当前生效的提示词存成命名方案（如「温柔版」「活泼版」），多套方案独立保存、互不干扰，随时切换 / 删除。方案持久化在插件数据目录的 `prompts.json`。
- **三级优先级**（高 → 低）：**激活方案** > **配置自定义** > **内置默认**。激活某方案后整体覆盖；取消激活则回退到配置自定义 / 内置默认。

命令用法：

| 命令 | 权限 | 说明 |
|------|------|------|
| `/下线通知 提示词` | 所有人 | 查看所有方案与当前生效来源 |
| `/下线通知 提示词 查看 <名称>` | 所有人 | 查看某方案的提示词内容 |
| `/下线通知 提示词 保存 <名称>` | 管理员 | 把当前生效的提示词存成命名方案 |
| `/下线通知 提示词 切换 <名称>` | 管理员 | 激活某方案（覆盖配置/默认） |
| `/下线通知 提示词 默认` | 管理员 | 取消激活，回退到配置/内置默认 |
| `/下线通知 提示词 删除 <名称>` | 管理员 | 删除某方案 |

> 典型工作流：在配置面板写好自定义提示词 → `/下线通知 提示词 保存 我的角色` 快照 → 切换到别的方案再保存另一套 → 随时 `/下线通知 提示词 切换 <名称>` 在多套间切换，互不丢失。

#### LLM 生成 vs 模板引擎

| 特性 | LLM 生成 | 模板引擎 |
|------|----------|----------|
| 内容多样性 | 每次不同，风格多变 | 始终相同，仅变量替换 |
| 自然度 | 像真人写的通知 | 固定格式 |
| 响应速度 | 取决于 LLM 响应时间（通常 1-5 秒） | 即时 |
| 依赖 | 需要配置 LLM 提供商 | 无需外部依赖 |
| 可靠性 | 可能超时或失败，但会自动回退 | 始终可用 |

#### 工作流程

```
定时触发
  │
  ▼
尝试 LLM 生成 ◄── 启用 LLM 生成？ ──► 否 ──► 使用模板引擎
  │                                           │
  ├─ 成功 ──► 使用 LLM 生成的内容            │
  │                                           │
  └─ 失败 ──► 回退到模板？ ──► 是 ──► 使用模板引擎
                  │
                  └─ 否 ──► 跳过本次通知
```

### 消息模板（回退方案）

消息模板控制通知消息的外观和内容。支持使用 `{变量名}` 插入动态内容。

#### 标题模板

**说明**：通知消息的标题行，通常用方括号包裹以突出显示。

**可用变量**：

| 变量 | 说明 | 示例值 |
|------|------|--------|
| `{time}` | 下线时间 | `23:00` |
| `{date}` | 当前日期 | `2026-07-07` |
| `{day_of_week}` | 星期几（中文） | `周二` |
| `{countdown_minutes}` | 剩余分钟数 | `5` |

**默认值**：`【AI服务下线通知】`

**使用示例**：

| 模板内容 | 渲染结果 |
|----------|----------|
| `【AI服务下线通知】` | `【AI服务下线通知】` |
| `【{day_of_week}下线提醒】` | `【周二下线提醒】` |
| `【{date} AI下线】` | `【2026-07-07 AI下线】` |

---

#### 正文模板

**说明**：通知消息的主体内容，是群成员看到的核心信息。

**可用变量**：

| 变量 | 说明 | 示例值 |
|------|------|--------|
| `{time}` | 下线时间 | `23:00` |
| `{date}` | 当前日期 | `2026-07-07` |
| `{day_of_week}` | 星期几（中文） | `周二` |
| `{countdown_minutes}` | 剩余分钟数 | `5` |
| `{emoji}` | 用户配置的表情符号 | `🌙` |

**默认值**：

```
各位成员请注意~

{emoji} AI助手即将在 {time} 下线休息，预计还有 {countdown_minutes} 分钟。

如有需要请尽快处理未完成的事项。
明天见！晚安~
```

**渲染示例**（假设当前为周二 22:55，下线时间 23:00）：

```
各位成员请注意~

🌙 AI助手即将在 23:00 下线休息，预计还有 5 分钟。

如有需要请尽快处理未完成的事项。
明天见！晚安~
```

**自定义示例**：

| 模板内容 | 渲染结果 |
|----------|----------|
| `晚安！AI将在 {time} 休息~` | `晚安！AI将在 23:00 休息~` |
| `{emoji} 还有 {countdown_minutes} 分钟就下线啦！` | ` 还有 5 分钟就下线啦！` |
| `今天是 {day_of_week}，{time} 准时下线哦~` | `今天是 周二，23:00 准时下线哦~` |

---

#### 表情符号

**说明**：用于正文中 `{emoji}` 变量的替换值，可以是任意 Unicode 表情符号。

**默认值**：`🌙`

**常用推荐**：

| 符号 | 含义 |
|------|------|
| `🌙` | 月亮（晚安） |
| `😴` | 睡觉 |
| `💤` | 休息 |
| `🌟` | 星星 |
| `👋` | 再见 |

**使用示例**：

### 目标群组

配置需要接收下线通知的QQ群列表。

| 字段 | 类型 | 说明 |
|------|------|------|
| `group_id` | 文本 | QQ群号，必填。请确保机器人已加入该群 |
| `group_name` | 文本 | 群名称备注，仅用于管理界面显示，不影响功能 |
| `enabled` | 开关 | 启用或禁用该群组的通知。禁用后该群不会收到通知 |

**注意**：如果未配置任何群组，通知将不会发送到任何地方。

### 重试配置

消息发送失败时的自动重试策略。

| 配置项 | 类型 | 默认值 | 允许范围 | 说明 |
|--------|------|--------|----------|------|
| 最大重试次数 | 整数 | 3 | 0-10 | 设为 0 则不重试。每次发送失败后自动重试，最多重试 N 次 |
| 重试基础间隔 | 整数（秒） | 10 | 5-120 | 实际等待时间 = 基础间隔 × 当前重试次数。例如基础间隔 10 秒，第 1 次重试等待 10 秒，第 2 次等待 20 秒，第 3 次等待 30 秒 |

### 自我监控配置

定时任务的健康检查和异常告警功能。

| 配置项 | 类型 | 默认值 | 允许范围 | 说明 |
|--------|------|--------|----------|------|
| 启用自我监控 | 开关 | 开启 | - | 关闭后不再进行心跳检测和告警 |
| 心跳检测间隔 | 整数（秒） | 300 | 60-3600 | 每隔 N 秒检查一次调度器是否正常运行 |
| 心跳超时阈值 | 整数（秒） | 180 | - | 调度器心跳年龄超过此值视为异常，默认为心跳检测间隔的 3 倍 |
| 告警通知群号 | 文本 | 空 | - | 调度器异常时，向此 QQ 群发送告警消息。留空则仅记录日志 |
| 告警通知QQ号 | 文本 | 空 | - | 调度器异常时，向此 QQ 号发送私聊告警消息。留空则不发送私聊告警 |

**告警触发条件**：

1. 调度器未运行（插件启动失败或被意外停止）
2. 调度器心跳超时（超过 3 倍心跳间隔未更新）

**告警冷却机制**：同一异常不会重复告警，两次告警之间至少间隔 30 分钟，避免告警轰炸。

**双通道告警**：`告警通知群号` 和 `告警通知QQ号` 可同时填写，异常时会同时向群和私聊发送告警。也可以只填其中一个，实现单通道告警。

### 通知发布记录

> **v1.2.0 新增**：持久化存储每次通知的发送历史，支持 WebUI 和命令查询。

系统自动记录每次通知发送的详细信息，包括触发时间、计划名称、实际提前分钟数、浮动秒数、消息来源（LLM/模板）和发送结果。

#### 记录内容

每条记录包含以下字段：

| 字段 | 说明 |
|------|------|
| 时间 | 通知实际发送时间 |
| 计划名称 | 触发该通知的调度计划 |
| 下线时间 | 配置的下线时间 |
| 提前分钟 | 配置的提前通知分钟数 |
| 实际提前 | 实际触发时的提前分钟数（含浮动影响） |
| 浮动秒数 | 实际浮动的秒数（0 表示精确触发） |
| 消息来源 | `llm`（LLM 生成）或 `template`（模板回退） |
| 发送结果 | 成功/失败的群组列表 |

#### 存储策略

- 存储格式：JSON 文件，保存在插件数据目录
- 最大记录数：200 条，超出后自动循环覆盖
- 并发安全：使用 asyncio.Lock 保护文件写入

### 手动生成命令（管理员专用）

> **v1.3.0 新增**：支持管理员在私聊中生成通知并发送到指定群。

#### 使用方式

在**私聊**中向机器人发送：

```
/下线通知 生成 [QQ群号]
```

例如：`/下线通知 生成 1006930720`

#### 权限控制

- **群聊模式**：`/下线通知 生成` 仅预览 LLM 生成结果，不发送
- **私聊模式**：`/下线通知 生成 [群号]` 仅管理员可用，非管理员会收到权限不足提示

#### 手动场景专用提示词

手动生成时使用与自动调度不同的提示词（MANUAL_PROMPT），区别在于：

- 不包含倒计时表述（如"还有X分钟"），因为手动触发时间不固定
- 聚焦于自然告知下线信息，语气更灵活
- 管理员可自定义下线时间场景

#### 工作流程

```
私聊：/下线通知 生成 [群号]
  │
  ├─ 权限校验 ──► 非管理员 ──► 拒绝
  │
  ├─ 格式校验 ──► 群号格式错误 ──► 提示
  │
  ├─ 调用 LLM 生成（MANUAL_PROMPT）
  │     │
  │     ├─ 成功 ──► 发送到指定群
  │     │
  │     └─ 失败 ──► 回退模板 ──► 发送到指定群
  │
  └─ 返回结果给管理员
```

### 调度器心跳机制

> **v1.3.0 新增**：调度器内部维护独立心跳，用于监控器判断调度器事件循环是否仍在运行。

#### 工作原理

- 调度器启动后，内部创建异步心跳任务，每 60 秒更新一次心跳时间戳
- 监控器通过检查心跳年龄判断调度器健康状态
- 心跳超时阈值：3 倍心跳检测间隔（默认 180 秒）
- 心跳超时触发告警（遵循告警冷却机制）

此机制确保即使 APScheduler 内部异常，监控器也能及时发现并告警。

## 长通知自动分段（按句切分）

> **v1.4.1 修复**：此前长通知（如约 70 字符的 LLM 通知）会以**单条消息**整体发送，无法被 `astrbot_plugin_splitter` 插件分段（因为离线通知通过 `context.send_message` 直接投递到指定群，该路径在 AstrBot 框架中**不经过** splitter 的 `on_decorating_result` 装饰钩子，否则 splitter 自身回发分段时会无限递归重切）。**v1.4.1 起，本插件自带按句切分能力**，长通知会被正确拆成多条消息逐段发送，且**完全不依赖 splitter 是否启用**。
>
> **v1.4.4 调整**：内置提示词改为 **16 岁真人女孩「砂糖」人设** 自然道别（见上方「内置提示词」），移除了原先「25-35 字 / 恰好两段 / 含下线时间与剩余分钟数」的硬约束；内容改为 1-2 句活泼口语，由 `{time_context}` 按昼夜注入离开理由（睡觉 / 有事），既规避 AI/系统口吻、也不写具体下线时刻。长内容仍由本插件按句自动分段发送。
>
> **v1.5.0 调整**：① 默认提示词自称改为「砂糖」（群友也叫"小砂糖"），恢复「真实的小姑娘」身份声明；② 提示词「明置」——新增配置项 `custom_builtin_prompt` / `custom_manual_prompt` 可在面板直接编辑；③ 新增命名方案库 `/下线通知 提示词` 命令，支持多套提示词独立保存 / 切换 / 删除（三级优先级：激活方案 > 配置自定义 > 内置默认）。

#### 分段机制

- **切分规则**：以 `。！？ ! ? ； ; \n` 作为句末切分点，分隔符附加到前一段末尾（与 splitter 简单模式语义一致）。
- **逐条发送**：多段内容通过 `GroupNotifier.send_to_group` 逐条 `context.send_message` 投递，段间默认间隔 `0.8s`（`SEGMENT_SEND_INTERVAL`），模拟真人节奏、避免刷屏 / 触发平台限流。
- **单条直通**：内容较短（无句末标点切分点）时直接单条发送，不会切出碎片。
- **`/下线通知 测试` 同样生效**：测试命令也会先按句切分再逐段 `event.send`，与正式群通知表现一致。
- **多群并行**：`send_to_groups` 对每个目标群独立切分发送，互不影响。

#### 内容规范化（与 splitter 协同的兼容层）

若您**同时**启用了 `astrbot_plugin_splitter`，本插件在生成 / 渲染通知后仍做一层「无信息损失」的规范化，使内容对 splitter 友好（避免被整体保护或切出空段）：

- **句末标点闭合**：确保每句、以及整段通知以句末标点结尾，分段后的最后一段也是完整句子。
- **去除结构性包裹**：自动剥离 Markdown 代码块（`` ``` ``）与思维链标签（`<think>`），保留正文内容。
- **折叠连续标点**：将连续相同的句末标点（如 `。。。`、`！！`）折叠为单个，避免空段或纯标点碎片。
- **折叠空行**：将 2 个以上连续换行合并。
- **正文零丢失**：仅做格式层规整，称呼、时间、祝福语等真实内容不做任何删改。

#### 提示词约束（v1.5.0 起：自然道别人设 + 明置/多方案）

LLM 生成提示词（`BUILTIN_PROMPT` / `MANUAL_PROMPT`）为 **16 岁真人女孩「砂糖」人设** 自然道别，并支持配置自定义与命名方案覆盖：

- **人设**：16 岁可爱活泼女生「砂糖」（群友也叫"小砂糖"），在群里像朋友一样相处，自称真实的小姑娘、不露 AI/机器人腔调；
- **禁用词**：AI、人工智能、机器人、助手、通知、系统、**下线**、离线、退出登录、挂机；且不写「XX:XX 下线」这种带具体时刻的写法；
- **自然口语**：活泼亲切，可加「呀、啦、咯、哦、~」语气词，一两句、别像公告，顺带道晚安 / 明天见即可；
- **昼夜情境**：由 `{time_context}` 注入（深夜去睡觉 / 傍晚休息 / 下午有事 / 上午有事），自然说明离开理由，不暴露后台调度语义（不塞 `offline_time` / `countdown_minutes`）；
- **格式合规**：纯文本、无 Markdown / `<think>` 标签 / 前缀解释；长内容由插件按句自动分段发送；
- **明置与多方案（v1.5.0）**：可在配置面板填写 `custom_builtin_prompt` / `custom_manual_prompt` 覆盖默认；也可用 `/下线通知 提示词` 命令保存多套命名方案、互不干扰地切换（优先级：激活方案 > 配置自定义 > 内置默认）。

这样既不暴露 AI 身份、也不写具体下线时刻，输出为 1-2 句自然道别，经本插件按句分段（或 splitter）输出。

#### 验证

内置测试 `tests/test_splitter_compat.py` 覆盖三类验证：

1. **`split_long_message` 自分段单测**：含用户真实反馈案例（约 70 字符通知正确切成 3 段）、语义完整、无空段 / 纯标点碎片、各前段以句末标点闭合、空串与无分隔符边界。
2. **`GroupNotifier.send_to_group` 集成测试**：验证多段内容确实以**多条独立 `send_message` 调用**投递到正确的群组 UMO，且拼接后内容无丢失。
3. **真实 splitter 管线集成测试**：用 splitter 插件源码验证规范化后的内容能被 splitter 正确分段（仅作兼容性保底）。

## 常见问题

### Q: 修改配置后不生效？

A: 修改 `_conf_schema.json` 中的默认值后，需要**重启 AstrBot** 才能生效。如果是在 WebUI 配置界面中修改，保存后也需要重启插件或 AstrBot。

### Q: 通知没有发送？

A: 按以下步骤排查：

1. 检查「启用下线通知」是否为开启状态
2. 检查「目标通知群组」中是否填写了正确的 QQ 群号
3. 检查对应群组的 `enabled` 开关是否为开启状态
4. 使用 `/下线通知 状态` 确认调度器是否正常运行
5. 使用 `/下线通知 测试` 手动发送测试通知

### Q: 如何只在工作日发送通知？

A: 在「定时通知计划」中，将工作日计划的 `day_type` 设为 `weekday`，将周末计划的 `enabled` 设为关闭即可。

### Q: 告警通知收不到？

A: 检查「自我监控配置」中的「告警通知群号」或「告警通知QQ号」是否已填写。注意：QQ号告警为私聊消息，需要确保机器人能与该用户私聊。

### Q: 支持哪些平台？

A: 目前支持 `aiocqhttp`、`qq`、`qq_official` 平台。

### Q: 浮动时间会导致通知发送太晚吗？

A: 不会。浮动范围始终在提前时间基础上增加延迟，即实际通知时间 = advance ~ advance + float_range 分钟。通知始终在设定的下线时间前发出，不会超过下线时间。

### Q: 多个计划同时触发时会怎样？

A: 浮动机制正是为了解决这个问题。即使多个计划设置相同的下线时间，由于每个计划独立随机浮动，实际发送时间会分散在浮动窗口内，不会同时发送。

### Q: LLM 生成的通知内容不好怎么办？

A: 可以关闭「启用 LLM 生成通知」开关，系统将使用模板引擎发送通知。模板内容可在「消息模板」配置中自定义。

### Q: LLM 生成太慢怎么办？

A: 可以调整 LLM 调用超时时间（默认 15 秒），或切换到更快的 LLM 模型。如果 LLM 超时，系统会自动回退到模板消息，不影响通知送达。

### Q: 浮动时间 x=0 时通知内容合理吗？

A: 当 x=0 时，通知中会显示"0 分钟后"，LLM 会生成即时下线的通知（如"我马上就要休息啦"），模板也会正常显示。

### Q: 如何查看通知的浮动历史？

A: 使用 `/下线通知 记录` 命令查看最近的通知发布记录，每行会显示实际的浮动秒数。WebUI 中的「通知发布记录」表格也提供完整的字段展示。

### Q: 如何升级到 v1.3.0？

A: 直接替换插件文件即可，配置项向后兼容。v1.3.0 新增的手动生成命令（管理员私聊模式）和调度器心跳机制使用默认配置即可生效。如从 v1.1.x 升级，浮动范围和通知记录功能会使用默认值（全局浮动范围 2 分钟），重启后即可生效。

### Q: 如何在私聊中手动向指定群发送通知？

A: 使用 `/下线通知 生成 [QQ群号]` 命令（例如 `/下线通知 生成 1006930720`），仅管理员可用。系统会使用手动场景专用提示词（MANUAL_PROMPT）生成通知，不包含倒计时表述，更自然。LLM 生成失败时自动回退到模板消息。

### Q: 调度器心跳是什么？

A: 调度器内部有一个独立的心跳任务，每 60 秒更新一次心跳时间戳。监控器通过检查心跳年龄来判断调度器的事件循环是否仍在正常运行。如果心跳超时（默认 180 秒），监控器会触发告警通知管理员。

### Q: 长通知还是没有被分段？

A: 自 **v1.4.1** 起，离线通知本身已具备按句分段能力，**无需依赖 splitter 插件**即可将长通知拆成多条消息逐段发送。排查要点：

1. 升级到 v1.4.1+：旧版本（v1.4.0 及之前）的长通知是单条发送的，不会自动分段；
2. 段间发送间隔默认为 `0.8s`（`SEGMENT_SEND_INTERVAL`），多条消息会在约 `段数 × 0.8s` 内陆续到达，属正常现象，并非只发了第一条；
3. 如果一条通知本身没有句末标点切分点（如纯模板短句），会被当作单条直接发送——这是预期行为，不是故障；
4. 若同时启用了 `astrbot_plugin_splitter`：本插件已做规范化（句末标点闭合、去代码块 / 思维链、折叠连续标点与空行），两段机制并存时内容仍能被正确、无重复地送达，不会因格式问题被整体吞掉或切出空段。
